# UX-02.2 — Gap Analysis: Teacher Onboarding Wizard

**Tanggal:** 2026-09-29  
**Status:** ANALYSIS COMPLETE — rekomendasi menunggu keputusan Human Architect  
**Scope:** Audit kesesuaian UX Teacher Onboarding Hub/Wizard terhadap intent terbaru. Tidak ada perubahan kode produk dalam pekerjaan ini.

## Ringkasan Eksekutif

Implementasi saat ini menggabungkan modal wizard dengan kartu progres permanen di area teratas dashboard. Modal terbuka untuk setiap snapshot onboarding yang belum seluruhnya `complete`; menutup modal hanya mengubah state lokal. Akibatnya, kartu tetap memenuhi ruang dashboard, dan modal dapat terbuka lagi saat halaman/komponen dibuat ulang. Cursor langkah wizard juga tidak tersimpan, walaupun status domain onboarding tertentu sudah disimpan server-side.

Intent terbaru Human Architect menghendaki dashboard tetap menjadi halaman utama, modal wizard menjadi surface sementara, dan tidak ada panel onboarding permanen setelah wizard ditutup atau onboarding selesai. Berdasarkan intent terbaru tersebut, implementasi memiliki gap UX yang nyata.

**Konflik dokumen:** spesifikasi UX-02 aktif saat ini justru menyetujui onboarding hub di dashboard dan secara eksplisit menolak modal pemblokir. Instruksi Human terbaru memiliki precedence tertinggi menurut AGENTS.md, tetapi dokumen canonical dan plan masih memuat keputusan lama. Sebelum perubahan kode, rekonsiliasikan keputusan ini pada spec/plan agar implementasi berikutnya memiliki kontrak yang konsisten.

## Intent Pembanding

Intent terbaru Human Architect untuk audit ini:

1. Dashboard tetap menjadi halaman utama.
2. Pada first login guru baru, glass modal wizard muncul di atas dashboard.
3. Wizard sementara: dapat ditutup, dan tidak menjadi panel dashboard permanen.
4. Setelah selesai atau ditutup, dashboard kembali normal tanpa panel onboarding besar.
5. Progress onboarding tersimpan server-side sehingga proses dapat dilanjutkan.
6. Dashboard guru yang telah onboarding bersih dari panel onboarding.

Spesifikasi UX-02 aktif yang ditemukan, [docs/specs/active/UX-02-SPEC.md](docs/specs/active/UX-02-SPEC.md), masih mendefinisikan perilaku berbeda: wizard modal dihapus dari first-login journey, satu onboarding hub ditampilkan di dashboard, dan hub dapat ditutup sementara. Plan aktif UX-02 juga merencanakan dashboard hub, bukan modal first-login. Ini adalah konflik kontrak, bukan sekadar perbedaan implementasi visual.

## Rekomendasi Sebelum Perubahan Kode

1. **Rekonsiliasi kontrak terlebih dahulu.** Catat intent modal first-login terbaru sebagai keputusan Human Architect pada UX-02 spec/plan. Tandai secara eksplisit bahwa keputusan lama “dashboard hub non-modal” digantikan; jangan biarkan implementasi mengikuti dua kontrak yang berlawanan.
2. **Tetapkan lifecycle modal.** Bedakan akun guru baru dari login guru lama dan tetapkan aturan first-login. Tentukan apakah menutup modal menyembunyikannya sampai login berikutnya atau sampai guru memilih aksi “Lanjutkan”; dashboard tetap tanpa panel onboarding besar dalam kedua keadaan.
3. **Tetapkan kontrak resume.** Simpan progress/cursor yang benar-benar diperlukan server-side dengan scope pengguna + tenant. Pada sesi berikutnya wizard harus melanjutkan dari checkpoint yang tersimpan, bukan memulai dari langkah pertama. Kegagalan aksi tidak boleh memajukan cursor atau menandai step complete.
4. **Tentukan semantik completion vs defer.** Definisikan apakah defer menyelesaikan wizard untuk lifecycle first-login atau hanya menyelesaikan checkpoint opsional. Jangan gunakan status progress sebagai pengganti status dismissal/modal. Selesai maupun dismiss harus mengembalikan dashboard tanpa panel permanen.
5. **Pisahkan wizard dari dashboard hub.** Rekomendasi struktur: dashboard hanya menjadi background; render modal secara kondisional dari status first-use/resume. Hapus kartu Resume onboarding dari layout dashboard. Jika resume manual dibutuhkan setelah dismiss, gunakan entry point kecil di lokasi dashboard yang sudah ada, bukan panel besar baru.
6. **Ganti regression contract sebelum implementasi.** Tambahkan coverage untuk first-login overlay, login ulang, dismiss tanpa panel, remount/resume pada cursor tersimpan, completion tanpa panel, status deferred, dan error/retry. Ubah assertion lama yang mensyaratkan kartu dan modal tampil bersamaan.
7. **Pertahankan domain dan security boundary.** Reuse snapshot/action server-side yang sudah tenant-scoped. Role preference tetap bukan permission; penyelesaian atau dismiss wizard tidak boleh memberi akses atau menciptakan assignment/data akademik sintetis.

## Kriteria Penerimaan yang Direkomendasikan

- Guru baru melihat dashboard sebagai halaman dasar dengan wizard overlay otomatis pada first login yang memenuhi syarat.
- Menutup wizard langsung menampilkan dashboard normal tanpa kartu/panel onboarding permanen.
- Guru yang kembali dapat melanjutkan melalui lifecycle/entry point yang diputuskan, pada checkpoint terakhir yang valid di server untuk tenant aktif.
- Login guru lama tidak otomatis membuka wizard berulang kecuali kontrak resume secara eksplisit menetapkan perilaku tersebut.
- Setelah wizard selesai, komponen onboarding tidak menghasilkan modal maupun panel pada dashboard production.
- UI status complete/deferred/pending konsisten dengan state yang disimpan dan tidak memengaruhi otorisasi.
